# Передача frontend после изменений backend

После получения ветки backend и её слияния обновите свою ветку и подключите интерфейс к реальному API. Задача frontend — завершить **весь пользовательский интерфейс проекта**, включая экраны и действия для разных ролей; существующие mocks и демонстрационные кнопки нужно заменить рабочими запросами.

1. **Поднять среду и принять контракт.** Запуск описан в [README backend](../../backend/README.md). API по умолчанию: `http://localhost:8080/api/v1`, Swagger: `http://localhost:8081`, письма: `http://localhost:8025`. Источник DTO и операций — [OpenAPI](../../backend/pkg/api/v1/openapi.yaml). Настройте единый HTTP-клиент и base URL; согласуйте CORS и `PUBLIC_WEB_URL` с адресом frontend.
2. **Реализовать аккаунты и доступ.** Регистрация с согласием, подтверждение e-mail, вход/выход, восстановление пароля, профиль и права ролей. Access передаётся как Bearer; refresh выполняется через `POST /auth/refresh` с полем `token` и заменяет оба токена. Параллельные запросы не должны независимо ротировать одну refresh-сессию. Регистрация возвращает 202 и требует подтверждения письма перед входом.
3. **Завершить предметные сценарии.** Каталоги и карточки, команды/состав/приглашения, создание и публикация турнира, заявки и их рассмотрение, жеребьёвка, сетка/таблицы, расписание, ввод и подтверждение результатов, споры и судейство, рейтинги, уведомления и администрирование. Состав экранов и действий определяйте по контракту и правам пользователя. Сетку, итоговые места и рейтинг берите с backend.
4. **Довести интеграцию.** Обработать пагинацию, поиск, состояния загрузки/пустого результата/ошибки, ответы 204 и конфликты `version`/409. Подключить загрузку файлов и авторизованное скачивание протоколов, CSV и публичные SSE-обновления турнира. Разрешать относительные URL файлов относительно API origin. После изменения данных перечитывать серверное состояние; сохранять корректность после обновления страницы и смены аккаунта.
5. **Выполнить свою часть ЛР3.** Выбрать семь подходящих метрик TypeScript/React, сохранить первоначальный замер и исходники, оптимизировать реальные сложные места, повторить измерение теми же инструментами и правилами отбора. Передать таблицу «до/после», примеры изменений, версии инструментов, результаты lint/build и короткие выводы для общего отчёта. Метрики разных языков анализируются отдельно.

Интеграция готова, когда основные сценарии выполняются с реальными данными backend, права разных аккаунтов работают, данные сохраняются после перезагрузки, а штатный UI не зависит от mocks. Детальную реализацию интерфейса frontend-разработчик определяет самостоятельно.
