# ЛР3. Анализ кода интерфейса TourneyHub

**Цель работы** — найти участки React-интерфейса, где вложенные условия затрудняют чтение, и измерить эффект рефакторинга.

## Методика

Исходная версия взята из ветки main, коммит `704b49a`. Оба замера охватывают все файлы .ts и .tsx в frontend/src, включая тестовые данные и типы. Файлы деклараций .d.ts исключены. Скрипт measure.mjs разбирает синтаксическое дерево средствами TypeScript 5.6.3 под Node.js 24.20.0. Показатели рассчитаны отдельно для клиентской части.

| Показатель | До | После | Изменение |
| --- | ---: | ---: | ---: |
| Файлы в выборке | 51 | 51 | 0 |
| Непустые физические строки, включая комментарии | 1468 | 1488 | +20 |
| Функции с телом, включая стрелочные | 121 | 122 | +1 |
| Условные выражения вида `a ? b : c` | 32 | 25 | −7 |
| Максимальная вложенность таких выражений | 3 | 2 | −1 |
| Логические операции `&&` и `||` | 20 | 20 | 0 |

Вложенность равна числу условных выражений на одном пути от корня синтаксического дерева. Один самостоятельный тернарный оператор даёт глубину 1.

## Разбор изменений

**Страница турнира.** До изменения цепочка из трёх тернарных операторов внутри JSX выбирала содержимое вкладки. Чтобы найти вариант по умолчанию, требовалось проследить все три уровня. Теперь компонент TournamentStage возвращает отдельный блок для плей-офф, участников и итогов. Общий возврат показывает таблицы групп и расписание, в том числе для вкладок groups и schedule. Все три проверки выбора вкладки сохранились, но вложенность тернарных выражений в этом фрагменте снизилась с 3 до 0.

**Карточка турнира.** Раньше подпись под индикатором заполнения выбиралась вложенным условием, а оформление и текст кнопки независимо проверяли статус регистрации. Теперь статус служит ключом для выбора подсказки и свойств кнопки. Например, для открытой регистрации карточка показывает число свободных мест и основную кнопку «Подать заявку», для завершённого турнира — «Итоги опубликованы» и вторичную кнопку «Открыть». Это убрало ещё четыре тернарных оператора.

## Проверка и вывод

ESLint 9.39.5 в обоих запусках завершился без ошибок, с одним предупреждением Fast Refresh в AuthProvider.tsx. Первоначальная сборка остановилась с TS2307 при импорте index.css. В итоговой версии добавлена декларация типов vite/client. После этого команда сборки выполнила проверку TypeScript и собрала приложение с Vite 5.4.21.

Число тернарных выражений сократилось примерно на 22%, максимальная глубина уменьшилась на один уровень. Объём вырос на 20 непустых строк и одну функцию из-за выделения компонента и явного описания состояний карточки. Результат относится к структуре исходного кода. Скорость отрисовки в работе не измерялась.

## Воспроизведение

Из корня репозитория при установленных зависимостях frontend выполните команды PowerShell:

```powershell
Expand-Archive docs/lab3/frontend/source-before.zip "$env:TEMP/TourneyHub-lab3-before" -Force
node docs/lab3/frontend/measure.mjs "$env:TEMP/TourneyHub-lab3-before/frontend/src"
node docs/lab3/frontend/measure.mjs frontend/src
cd frontend
npm run lint
npm run build
```

Первоначальные исходники находятся в source-before.zip. Файлы before.json и after.json содержат результаты двух запусков анализатора.
