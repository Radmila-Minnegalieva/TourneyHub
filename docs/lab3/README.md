# Лабораторная работа 3 Метрики кода backend TourneyHub

В серверной части ЛР3 выполнены первоначальное измерение, анализ результатов, оптимизация кода и повторное измерение. В отчёт включены семь метрик Go-кода. Материалы frontend добавляются после выполнения работы вторым участником команды.

## Материалы

- Готовые Word- и PDF-отчёты находятся в каталоге `ТРПО`, рядом с папкой репозитория `TourneyHub`. Word-файл формируется командой `python3 docs/lab3/build-report.py`; каталог можно задать через `--output-dir`.
- [Первоначальное измерение](metrics-before.json) и [повторное измерение](metrics-after.json).
- [Исходники первоначального замера](source-before.tar.gz) и [исходники повторного замера](source-after.tar.gz).
- [Подготовка к защите и объяснение backend](defense-guide.md). Word-версия формируется командой `python3 docs/lab3/build-defense.py` в тот же каталог `ТРПО` рядом с репозиторием.

## Методика

Измеритель `backend/cmd/metrics` использует стандартные пакеты `go/parser`, `go/ast`, `go/scanner` и анализаторы gocyclo **v0.6.0** и gocognit **v1.2.0**. Оба замера выполнены с Go **1.27.2**. Версии анализаторов закреплены в `go.mod`; команда `make metrics` также запускает их нативные CLI.

В каждом замере исследуется весь написанный вручную production-код backend по одинаковым правилам отбора. Исключены `*_test.go`, сгенерированные файлы, `vendor`, `build`, `bin`, сам измеритель `cmd/metrics` и инструменты из `tools`. Для каждого измеренного файла в JSON сохранён SHA-256.

Состав файлов между замерами изменился. Поэтому сравнение относится к двум полным снимкам исходников, а не к одному неизменному списку файлов. Размер кода и усреднённые характеристики зависят от состава выборки и сами по себе не доказывают улучшения качества.

Для отчёта выбраны ровно семь показателей. JSON сохраняет подробный результат анализатора; в таблицу отчёта включены только следующие метрики:

| Метрика | Определение |
| --- | --- |
| Максимальная цикломатическая сложность CC | Наибольшее значение gocyclo среди функций и методов: базовая единица плюс ветвления, циклы и логические операторы |
| Максимальная когнитивная сложность | Наибольшее значение gocognit с учётом ветвлений, их вложенности и правил анализатора |
| Физические строки LOC | Все строки измеряемых файлов, включая пустые строки и комментарии |
| Строки кода SLOC | Строки с Go-токенами, включая все строки многострочных литералов; комментарии и автоматически вставленные scanner точки с запятой исключены |
| Максимальная длина функции | Наибольшее число физических строк от объявления функции до закрывающей скобки |
| Доля комментариев | `comment_lines / source_lines × 100`; одна строка может содержать и код, и комментарий |
| Максимальный fan out пакета | Наибольшее число уникальных импортируемых пакетов для одного собственного пакета, включая стандартную библиотеку |

При анализе функций использованы ориентиры CC > 10, cognitive > 15 и длина > 60 строк. Они помогают выбрать участки для оптимизации, но не являются универсальными нормами Go или доказательством ошибки. Глубина наследования классов к Go неприменима; fan out не подменяет .NET class coupling.

## Первоначальное и повторное измерения

| Метрика | Первоначальное измерение | Повторное измерение |
| --- | ---: | ---: |
| Максимальная цикломатическая сложность CC | 27 | 19 |
| Максимальная когнитивная сложность | 55 | 25 |
| Физические строки LOC | 5841 | 9479 |
| Строки кода SLOC | 5482 | 8381 |
| Максимальная длина функции, строк | 82 | 59 |
| Доля комментариев, % | 1,75 | 3,47 |
| Максимальный fan out пакета | 44 | 24 |

После оптимизации уменьшились максимальные значения сложности, длины функции и числа импортируемых пакетов. Выделение отдельных проверок и вспомогательных функций позволило сократить вложенность и длину наиболее сложных операций.

LOC и SLOC увеличились. Эти показатели характеризуют общий объём исходников: добавление вспомогательных функций, проверок и явных объявлений может увеличивать число строк при упрощении отдельных участков. Рост доли комментариев также не означает автоматического улучшения их содержания. Выводы об оптимизации следует подтверждать анализом конкретных изменений, приведённых в отчёте.

## Воспроизведение

Команды выполняются из `backend/`. Повторный вывод сохраняется в `build/`, чтобы исходные результаты лабораторной оставались неизменными:

```sh
make metrics
mkdir -p build/metrics/replay/before build/metrics/replay/after
tar -xzf ../docs/lab3/source-before.tar.gz -C build/metrics/replay/before
tar -xzf ../docs/lab3/source-after.tar.gz -C build/metrics/replay/after
go run ./cmd/metrics -root build/metrics/replay/before -out build/metrics/recomputed-before.json
go run ./cmd/metrics -root build/metrics/replay/after -out build/metrics/recomputed-after.json
```

Проверка измеренных данных:

```sh
python3 - <<'PY'
import json
from pathlib import Path

for stage in ("before", "after"):
    expected = json.loads(Path(f"../docs/lab3/metrics-{stage}.json").read_text())
    actual = json.loads(Path(f"build/metrics/recomputed-{stage}.json").read_text())
    for field in ("summary", "package_fan_out", "files", "functions"):
        assert actual[field] == expected[field], (stage, field)
    print(stage, "measured fields match")
PY
```

Текст `scope` в текущем измерителе дополнен исключением `tools/`, которого не было в первоначальном снимке; состав измеренных файлов этого снимка не меняется. Поле `go_version` описывает среду запуска. Поэтому сравниваются измеренные разделы JSON, а не побайтовое представление всего файла.

Архивы содержат измеряемые Go-файлы и соответствующие `go.mod`/`go.sum`. Они предназначены для повторного статического измерения; исключённые из выборки файлы в них не входят.

| Архив | SHA-256 |
| --- | --- |
| `source-before.tar.gz` | `805f8c70ae94aecc01e806ccda1d306eca657446b0d8b3b1239239c6a6151d46` |
| `source-after.tar.gz` | `7c4a3aeda222ef0f02e2986469d9f060dbd7f0248e44cbf82efc8a203896cb3d` |

Отчёт пересобирается командой `python3 docs/lab3/build-report.py` из корня репозитория при установленном `python-docx`; таблицы читаются из сохранённых JSON. После изменения измеряемого кода исходники, замеры и документы обновляются согласованно.
