# Запуск тестового стенда TourneyHub

Стенд поднимает фронтенд, Go API, PostgreSQL 16, Mailpit и Swagger. Docker загружает снимок тестовых данных, а скрипт создаёт пароли и подставляет их вместе со ссылками в пошаговые кейсы.

## Что нужно заранее

- Git, запущенный Docker Desktop с Linux-контейнерами или Docker Engine с Compose 2.24.4 и новее, Node.js 22 или 24.
- Для публичной ссылки — свой аккаунт ngrok и [authtoken из кабинета ngrok](https://dashboard.ngrok.com/get-started/your-authtoken). Для локальной проверки токен не нужен.
- Выполняй команды из корня клонированного репозитория, где лежит `compose.yaml`. `npm install` на хосте не требуется. Docker установит зависимости при сборке.

Проверь доступ к движку и версии инструментов.

```text
docker version
docker compose version
node --version
```

## Первый запуск на Windows PowerShell

Введи токен со скрытым вводом. Он передаётся контейнеру ngrok и не записывается в файлы репозитория. Остальные сервисы публикуются только на localhost.

```powershell
$token = Read-Host 'Токен ngrok' -AsSecureString
$env:NGROK_AUTHTOKEN = [System.Net.NetworkCredential]::new('', $token).Password
try {
    node tests/qa-setup.mjs
} finally {
    Remove-Item Env:NGROK_AUTHTOKEN -ErrorAction SilentlyContinue
}
```

На Linux или macOS с Bash используй аналогичную команду.

```bash
read -rsp 'Токен ngrok: ' NGROK_AUTHTOKEN
printf '\n'
NGROK_AUTHTOKEN="$NGROK_AUTHTOKEN" node tests/qa-setup.mjs
unset NGROK_AUTHTOKEN
```

При первом запуске Docker скачает образы и соберёт приложение. Скрипт закончит работу после ответа фронтенда, API и Mailpit. Он напечатает HTTPS-ссылку ngrok и пути к готовым файлам.

| Куда идти | Адрес или файл |
|---|---|
| Фронтенд | Публичная ссылка из вывода команды или [localhost:5173](http://localhost:5173/tournaments) |
| Письма регистрации, сброса пароля и уведомлений | [Mailpit на localhost:8025](http://localhost:8025) |
| Проверки через API | [Swagger на localhost:8081](http://localhost:8081) |
| Кого выбрать для каждого сценария | `tests/.qa/tourneyhub-qa/test-cases.md` |
| Все логины и сгенерированные пароли | `tests/.qa/tourneyhub-qa/accounts.md` |

**Открой именно сгенерированный `test-cases.md`.** В нём уже стоят фактические адреса, логины и пароли. В Git хранится шаблон кейсов, который работает и на другом адресе. Папка `tests/.qa/` исключена из Git. Администратор и организаторы получают отдельные пароли для каждого стенда.

**Mailpit открывается на том компьютере, где запущен Docker.** Через ngrok доступно приложение вместе с его API. База, Swagger и почта остаются локальными. Ссылки из новых писем ведут на адрес, с которым запущен стенд. Если запускала локальную версию, а потом включила ngrok, для публичной проверки запроси новое письмо после включения туннеля.

## Локальный запуск и повторная проверка

```text
node tests/qa-setup.mjs --local
```

Команда без `--local` включает ngrok. Повторный запуск с тем же именем проекта и портами сохраняет пароли и результаты предыдущих проверок. Для повторения кейсов, которые меняют данные, создай новый проект. Например, на PowerShell:

```powershell
$env:TOURNEYHUB_QA_PROJECT = 'tourneyhub-qa-second'
$env:TOURNEYHUB_QA_PORT_OFFSET = '10000'
node tests/qa-setup.mjs --local
```

Тогда фронтенд будет на `15173`, Mailpit на `18025`, Swagger на `18081`, а пароли и кейсы в `tests/.qa/tourneyhub-qa-second/`. Чтобы опубликовать этот стенд через ngrok, останови туннель предыдущего проекта или используй свой свободный адрес и аккаунт. В пределах одного бесплатного аккаунта параллельный запуск может конфликтовать с уже открытым адресом.

Остановить приложение и туннель с сохранением базы можно так. Для нестандартного проекта перед остановкой задай те же переменные, что при запуске.

```text
node tests/qa-setup.mjs --stop
```

## Если что-то не открывается

- **Docker Engine недоступен.** Запусти Docker Desktop и дождись, чтобы `docker version` показал Server. Сборка требует свободного места на системном диске.
- **Порт занят.** Если на машине уже есть TourneyHub или Mailpit, используй другое имя проекта и смещение портов, как в примере выше.
- **ngrok вернул `ERR_NGROK_3200`.** Проверь, что Docker и контейнер туннеля работают. Для стандартного имени команда диагностики — `docker logs --tail 30 tourneyhub-qa-ngrok`. Если нужно заменить токен, удали только контейнер `tourneyhub-qa-ngrok` после его остановки и повтори запуск с новым токеном. Том базы остаётся на месте.
- **Письмо не видно.** Убедись, что открыт Mailpit именно этого проекта. Проверь адрес получателя и повторно запроси письмо после смены публичного URL.

Содержимое и роли исходного набора описаны в [демоданных](demo-data.md). Ручные сценарии основаны на функциональных требованиях FR-01–FR-41 из ТЗ ЛР1.
